# Agent Note: 浏览器演示必须由用户明确要求

Status: implemented

[English](2026-08-15-explicit-browser-gif-evidence.md) | 中文

## 问题

把每项产品可见的 GUI 变更或 PR（Pull Request）都视为浏览器演示请求，会迫使 agent（智能体）构建并启动真实 Web 服务、消耗真实模型凭据、操作浏览器、捕获媒体并修改远程 assets 分支，即使聚焦测试已经覆盖该变更也不例外。凭据可用还会意外触发真实提供方验证。对于快速修复和个人 fork，这种交付成本并不相称；创建 PR 本身也不代表用户授权了这些本地或远程操作。

## 决策

只有用户明确要求展示效果、进行浏览器验收、截图、录制 GIF 或视频，或提供 UI 演示时，才可以为了演示启动真实 Web 服务、控制浏览器、捕获媒体或调用 [`record-browser-gif`](../../../skills/record-browser-gif/SKILL.md)。产品用户可见行为、Web/UI 范围以及创建或更新 PR 都不足以触发这些操作。skill（技能）元数据禁止隐式调用，使受支持的 agent 能够机械识别这条规则。

默认交付采用最小实现以及变更约定所属的最窄证据：聚焦测试、必要的类型检查或 lint，并且只有预期输出套件负责该输出时才运行快照。用户要求快速修复或工作位于个人 fork 时，优先完成这种最小验证、提交与 PR，而不是扩展为面向上游的演示工作。

真实提供方 e2e 与浏览器证据相互独立。只有提供方/API 兼容性变更确实需要真实验证、凭据可用且用户授权调用时才运行。真实 API 运行绝不授权启动 Web UI、进行浏览器验收、截图、录制或发布媒体。

只有用户明确要求把 GIF、截图或视频证据附加到 PR 时，才创建或更新仅含媒体的 assets 分支。用户明确要求录制或发布后，现有[浏览器 GIF 证据链决策](2026-08-08-browser-gif-evidence-chain.md)继续约束来源完整性、来源说明、验证以及仅含媒体的发布方式。

本决策取代 [GUI 测试系统](2026-07-20-gui-testing-system.md)中的本地自动交付时机，但保留各测试车道的职责与无密钥 CI 浏览器回放门禁。CI 政策不会因此变成默认的本地浏览器运行要求。

## 考虑过的替代方案

**要求每项 GUI PR 都提供真实模型 GIF。** 这种方式默认向评审者提供视觉证据，但会消耗凭据、创建远程状态，并延迟已由聚焦确定性测试负责回归验证的变更。

**把凭据可用视为授权。** 环境状态只能说明可以发起调用，不能说明用户批准了成本、数据传输或外部副作用。

**每项可见变更都在本地运行浏览器回放。** CI 回放门禁已经覆盖全仓浏览器承载。只有用户明确要求浏览器验收时，才有理由在本地操作浏览器；可见性或排障本身并不足够。

**发布每项本地录制产物。** 录制与远程发布具有不同的副作用。用户要求本地演示，并不意味着要创建 assets 分支或修改 PR 正文。

## 后果

个人 fork 和快速修复的交付范围会与代码变更保持相称。只有用户提出要求时，评审者才会收到浏览器或媒体证据；CI 仍保留确定性的浏览器覆盖。agent 必须分别判断测试归属、真实提供方授权、浏览器演示与媒体发布，不能再从其中一项自动升级到下一项。用户明确要求演示时，仍需承担现有证据链所要求的成本，因为最终产物必须能够支撑它所表达的主张。
